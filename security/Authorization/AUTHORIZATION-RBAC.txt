Analogy: Airport Security

🎫 **AUTHENTICATION** - "Who are you?"
- Show your ID/passport
- Prove your identity
- "Yes, you are John Doe"

🚪 **AUTHORIZATION** - "What can you access?"
- Check your boarding pass
- First class vs Economy
- "You can access Gate 5, Seat 12A"


Real-World:

╔═══════════════════════════╦═══════════════════════════════════════╗
║      AUTHENTICATION       ║          AUTHORIZATION                ║
╠═══════════════════════════╬═══════════════════════════════════════╣
║ Login with username/pass  ║ Check if user has permission          ║
║ JWT token verification    ║ Check user's role (admin, user)       ║
║ "Are you logged in?"      ║ "Can you access this resource?"       ║
║ Happens ONCE (login)      ║ Happens on EVERY request              ║
╚═══════════════════════════╩═══════════════════════════════════════╝


Example:

// Authentication (Login)
POST /api/login
{ "email": "john@example.com", "password": "..." }
→ Returns JWT token
→ "You are John Doe" ✅

// Authorization (Access)
GET /api/admin/users
Header: Authorization: Bearer <token>
→ Check if John has 'admin' role
→ "John is a regular user, access denied" ❌

**RBAC** = Assign ROLES to users, assign PERMISSIONS to roles

Hierarchy:

USER → assigned to → ROLE → has → PERMISSIONS

// 1. Users Table
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

// 2. Roles Table
CREATE TABLE roles (
  id SERIAL PRIMARY KEY,
  name VARCHAR(50) UNIQUE NOT NULL,  -- 'admin', 'editor', 'viewer'
  description TEXT
);

// 3. Permissions Table
CREATE TABLE permissions (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) UNIQUE NOT NULL,  -- 'users:create', 'posts:edit'
  description TEXT
);

// 4. User-Role Relationship (Many-to-Many)
CREATE TABLE user_roles (
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  role_id INTEGER REFERENCES roles(id) ON DELETE CASCADE,
  PRIMARY KEY (user_id, role_id)
);

// 5. Role-Permission Relationship (Many-to-Many)
CREATE TABLE role_permissions (
  role_id INTEGER REFERENCES roles(id) ON DELETE CASCADE,
  permission_id INTEGER REFERENCES permissions(id) ON DELETE CASCADE,
  PRIMARY KEY (role_id, permission_id)
);

// user.entity.ts
import { Entity, PrimaryGeneratedColumn, Column, ManyToMany, JoinTable } from 'typeorm';
import { Role } from './role.entity';

@Entity('users')
export class User {
  @PrimaryGeneratedColumn()
  id: number;

  @Column({ unique: true })
  email: string;

  @Column()
  password: string;

  @ManyToMany(() => Role, role => role.users, { eager: true })
  @JoinTable({ name: 'user_roles' })
  roles: Role[];

  // Helper method to check if user has role
  hasRole(roleName: string): boolean {
    return this.roles.some(role => role.name === roleName);
  }

  // Helper method to get all permissions
  getAllPermissions(): string[] {
    const permissions = new Set<string>();

    for (const role of this.roles) {
      for (const permission of role.permissions) {
        permissions.add(permission.name);
      }
    }

    return Array.from(permissions);
  }

  // Helper method to check if user has permission
  hasPermission(permissionName: string): boolean {
    return this.getAllPermissions().includes(permissionName);
  }
}


// role.entity.ts
import { Entity, PrimaryGeneratedColumn, Column, ManyToMany } from 'typeorm';
import { User } from './user.entity';
import { Permission } from './permission.entity';

@Entity('roles')
export class Role {
  @PrimaryGeneratedColumn()
  id: number;

  @Column({ unique: true })
  name: string; // 'admin', 'editor', 'viewer'

  @Column({ nullable: true })
  description: string;

  @ManyToMany(() => User, user => user.roles)
  users: User[];

  @ManyToMany(() => Permission, permission => permission.roles, { eager: true })
  @JoinTable({ name: 'role_permissions' })
  permissions: Permission[];
}

  description: string;

  @ManyToMany(() => Role, role => role.permissions)
  roles: Role[];
}

// 1. Roles Guard - Check if user has required role
import { Injectable, CanActivate, ExecutionContext } from '@nestjs/common';
import { Reflector } from '@nestjs/core';

export const ROLES_KEY = 'roles';
export const Roles = (...roles: string[]) => SetMetadata(ROLES_KEY, roles);

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    // Get required roles from decorator
    const requiredRoles = this.reflector.getAllAndOverride<string[]>(ROLES_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);

    if (!requiredRoles) {
      return true; // No roles required
    }

    const request = context.switchToHttp().getRequest();
    const user = request.user;

    if (!user) {
      return false; // Not authenticated
    }

    // Check if user has ANY of the required roles
    return requiredRoles.some(role => user.hasRole(role));
  }
}


// 2. Permissions Guard - Check if user has required permission
export const PERMISSIONS_KEY = 'permissions';
export const RequirePermissions = (...permissions: string[]) =>
  SetMetadata(PERMISSIONS_KEY, permissions);

@Injectable()
export class PermissionsGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredPermissions = this.reflector.getAllAndOverride<string[]>(
      PERMISSIONS_KEY,
      [context.getHandler(), context.getClass()],
    );

    if (!requiredPermissions) {
      return true;
    }

    const request = context.switchToHttp().getRequest();
    const user = request.user;

    if (!user) {
      return false;
    }

    // Check if user has ALL required permissions
    return requiredPermissions.every(permission =>
      user.hasPermission(permission)
    );
  }
}

import { Controller, Get, Post, Delete, UseGuards } from '@nestjs/common';
import { JwtAuthGuard } from './guards/jwt-auth.guard';
import { RolesGuard } from './guards/roles.guard';
import { PermissionsGuard } from './guards/permissions.guard';
import { Roles } from './decorators/roles.decorator';
import { RequirePermissions } from './decorators/permissions.decorator';

@Controller('users')
@UseGuards(JwtAuthGuard, RolesGuard, PermissionsGuard)  // Apply guards
export class UsersController {

  // 1. Using Roles - Admin or Moderator can access
  @Get()
  @Roles('admin', 'moderator')
  async getAllUsers() {
    return this.usersService.findAll();
  }

  // 2. Using Permissions - Anyone with 'users:create' permission
  @Post()
  @RequirePermissions('users:create')
  async createUser(@Body() createUserDto: CreateUserDto) {
    return this.usersService.create(createUserDto);
  }

  // 3. Admin only
  @Delete(':id')
  @Roles('admin')
  async deleteUser(@Param('id') id: string) {
    return this.usersService.delete(id);
  }

  // 4. Multiple permissions required (user needs ALL)
  @Post(':id/promote')
  @RequirePermissions('users:edit', 'users:promote')
  async promoteUser(@Param('id') id: string) {
    return this.usersService.promoteToAdmin(id);
  }

  // 5. Public endpoint (no guards applied)
  @Get('public')
  async getPublicInfo() {
    return { message: 'This is public' };
  }
}

// posts.controller.ts
@Put(':id')
@UseGuards(JwtAuthGuard)
async updatePost(
  @Param('id') id: string,
  @Body() updatePostDto: UpdatePostDto,
  @Req() req,
) {
  const post = await this.postsService.findOne(id);

  if (!post) {
    throw new NotFoundException('Post not found');
  }

  // Check ownership
  if (post.authorId !== req.user.id && !req.user.hasRole('admin')) {
    throw new ForbiddenException('You can only edit your own posts');
  }

  return this.postsService.update(id, updatePostDto);
}


// Better: Create a Policy class
class PostPolicy {
  static canEdit(user: User, post: Post): boolean {
    // Admin can edit any post
    if (user.hasRole('admin')) {
      return true;
    }

    // User can edit their own post
    if (post.authorId === user.id) {
      return true;
    }

    // Moderator can edit posts in their category
    if (user.hasRole('moderator') && post.category === user.moderatorCategory) {
      return true;
    }

    return false;
  }

  static canDelete(user: User, post: Post): boolean {
    return user.hasRole('admin') || post.authorId === user.id;
  }

  static canPublish(user: User, post: Post): boolean {
    return user.hasRole('admin') || user.hasRole('editor');
  }
}

// Usage
@Put(':id')
async updatePost(@Param('id') id: string, @Req() req, @Body() dto: UpdatePostDto) {
  const post = await this.postsService.findOne(id);

  if (!PostPolicy.canEdit(req.user, post)) {
    throw new ForbiddenException('Cannot edit this post');
  }

  return this.postsService.update(id, dto);
}

✅ Fine-grained control

"Allow if user.department === resource.department AND user.level >= resource.securityLevel"

Q1: Explain RBAC and how you've implemented it.

A: "RBAC stands for Role-Based Access Control. Instead of assigning permissions
directly to users, you:

1. Create ROLES (admin, editor, viewer)
2. Assign PERMISSIONS to roles (users:create, posts:edit)
3. Assign ROLES to users

**Benefits:**
- Easy to manage (change role, all users updated)
- Clear hierarchy
- Scalable

**My Implementation:**
- Database: Users, Roles, Permissions (many-to-many)
- NestJS Guards: RolesGuard, PermissionsGuard
- Decorators: @Roles('admin'), @RequirePermissions('posts:edit')

In my last project, I implemented RBAC for a content management system with
4 roles (admin, editor, author, viewer) and 20+ permissions. This made it
easy to onboard new users and maintain security policies."


Q2: How do you handle role changes without requiring re-login?

A: "Two approaches:

**1. Short-lived tokens (Recommended):**
- Access token expires in 15 minutes
- Refresh token fetches new token with updated roles
- User gets new permissions automatically on next token refresh

**2. Cache invalidation:**
- Backend maintains token blacklist in Redis
- When role changes, add old tokens to blacklist
- On next request, token is rejected, user must refresh

**3. Real-time updates (WebSocket):**
- Server sends 'role-updated' event via WebSocket
- Frontend fetches new token immediately
- User sees new permissions instantly

I prefer option 1 for simplicity - 15 minute delay is acceptable for most apps."


Q3: How do you prevent privilege escalation attacks?

A: "Multiple safeguards:

**1. Server-side validation (NEVER trust client):**
@Post('users/:id/change-role')
async changeRole(@Param('id') id: string, @Body() dto: ChangeRoleDto, @Req() req) {
  // Check: Can current user change roles?
  if (!req.user.hasPermission('users:change-role')) {
    throw new ForbiddenException();
  }

  // Check: Is target role valid?
  if (!['admin', 'editor', 'viewer'].includes(dto.newRole)) {
    throw new BadRequestException('Invalid role');
  }

  // Check: User can't promote to higher role than themselves
  if (dto.newRole === 'admin' && !req.user.hasRole('super-admin')) {
    throw new ForbiddenException('Cannot promote to admin');
  }

  return this.usersService.changeRole(id, dto.newRole);
}

**2. Audit logging:**
- Log all role changes
- Monitor for suspicious patterns
- Alert on mass promotions

**3. Separate 'super-admin' role:**
- Only super-admin can create admins
- Regular admin cannot escalate to super-admin

**4. API key for sensitive operations:**
- Changing roles requires additional API key
- Stored separately, rotated regularly"

Authentication: "Who are you?" → Login, JWT
Authorization: "What can you access?" → Roles, Permissions

RBAC Flow:
1. User logs in → Get JWT with roles
2. User makes request → Guards check roles/permissions
3. If authorized → Process request
4. If not authorized → Return 403 Forbidden

Implementation:
- Database: 5 tables (users, roles, permissions, user_roles, role_permissions)
- Guards: RolesGuard, PermissionsGuard
- Decorators: @Roles(), @RequirePermissions()
- Policy classes: For resource-based checks

Best Practice: Role + Ownership check
- "User must have 'editor' role AND own the post"
