✅ 1. How would you containerize a full backend service (Node.js + PostgreSQL)? What are the key considerations?

Create separate services for the app and database using Docker Compose.
Use volumes for data persistence.
Use environment variables securely for configuration.
Add health checks.


version: '3.8'
services:
  backend:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DB_HOST=postgres
      - DB_PORT=5432
    depends_on:
      - postgres

  postgres:
    image: postgres:15
    restart: always
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: pass

      - pgdata:/var/lib/postgresql/data

✅ 2. How do you handle secrets in a Dockerized environment?

Avoid hardcoding secrets in Dockerfiles or Compose files.
Use:
    .env files (ignored via .gitignore)
    docker secrets (for Docker Swarm)
    External secret managers (Vault, AWS Secrets Manager, etc.)

In CI/CD, inject secrets via environment variables during build/deploy time.



✅ 3. What are the common Docker issues in production and how do you handle them

Memory leaks: Use monitoring and container limits (mem_limit).
Dangling volumes/images: Clean up regularly using docker system prune.
Logs growing indefinitely: Use logging drivers like json-file with size limits, or centralize with ELK stack.
Container restarts: Use restart: unless-stopped or on-failure.


✅ 4. How do you update Dockerized services with zero downtime?

Use a reverse proxy (e.g., Nginx, Traefik) with health checks.
Deploy updated container alongside old one.
Wait for new one to be healthy.
Switch traffic (blue-green or rolling deploy strategy).
In Kubernetes: use rolling deployments with readiness/liveness probes.



✅ 5. How would you debug a memory spike or crash in a Docker container?

Inspect logs: docker logs <container>
Check container stats: docker stats
SSH into container: docker exec -it <container> /bin/sh
If using Node.js, use tools like:
    heapdump or clinic.js
    Attach remote debugger
If using orchestration: check Pod/container metrics (Prometheus, Grafana)

✅ 7. How would you scale a Dockerized backend service?

Horizontally: run multiple containers behind a load balancer (HAProxy, Nginx, or Kubernetes Service).
Docker Compose:
    docker-compose up --scale backend=4
Use orchestration (Kubernetes, Docker Swarm) to auto-scale based on CPU/memory.




✅ 8. How do you handle database migrations in Dockerized CI/CD?

Add a separate migration step in your pipeline:
    Run npx prisma migrate deploy or sequelize db:migrate
Example Docker Compose entry:
    command: ["sh", "-c", "npm run migrate && npm start"]
Or separate migration container before app starts.


✅ 9. How do you optimize Docker images for production?

Use multi-stage builds:

FROM node:18 as builder
WORKDIR /app
COPY . .
RUN npm ci && npm run build

FROM node:18-alpine
WORKDIR /app
COPY --from=builder /app/dist .
RUN npm ci --only=production
CMD ["node", "main.js"]


Use .dockerignore
Keep base image small (alpine)
Don't run as root — use a non-root user


✅ 10. What’s the role of a reverse proxy in Dockerized backend deployment?

Handles SSL termination
Acts as a load balancer for multiple backend instances
Routes requests to correct service
Examples:
    Nginx reverse proxy with proxy_pass
    Traefik dynamic routing
    In Kubernetes: Ingress Controller
