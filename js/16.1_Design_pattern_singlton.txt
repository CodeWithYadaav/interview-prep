🌱 What Are Design Patterns?
Design patterns are reusable solutions to common problems in software design. They are like templates that help you write code that is:

Easier to understand

More maintainable

Scalable and testable



They're not code you copy-paste, but ideas or approaches you adapt to your situation. Think of them like tried-and-tested blueprints.



There are 3 main categories:

Creational Patterns – How objects are created.

Structural Patterns – How objects are composed/connected.

Behavioral Patterns – How objects interact and behave.



🧱 Let’s Start With the Singleton Pattern (Creational Pattern)
🔑 What Problem Does Singleton Solve?
Sometimes, you want to make sure that:

Only one instance of a class exists during the program’s lifetime.

That one instance can be accessed from anywhere.

Example in real life:

A printer manager in an office. You don’t want multiple managers fighting for control. Just one.

🔍 What Is a Class and Constructor? (Simple terms)
Let’s say you want to create a person in JavaScript:

class Person {
  constructor(name) {
    this.name = name;
  }

  sayHello() {
    console.log(`Hello, my name is ${this.name}`);
  }
}

const p1 = new Person("Alice");
p1.sayHello(); // Hello, my name is Alice



✅ Now Let’s Build a Singleton Step-by-Step
We want:

Only 1 object of the class.

Every time we "create" a new one, it gives us the same instance.

🔧 Singleton in JavaScript:
class Singleton {
  constructor() {
    if (Singleton.instance) {
      return Singleton.instance;
    }

    this.data = "I am the only instance";
    Singleton.instance = this;
  }

  showData() {
    console.log(this.data);
  }
}

const a = new Singleton();
const b = new Singleton();

console.log(a === b); // true, both are the same object
a.showData();         // I am the only instance
b.showData();         // I am the only instance


🧠 What's Happening?
Singleton.instance is a static property – it belongs to the class, not to each object.

The first time you create an object, it saves the object in Singleton.instance.

The next time, instead of creating a new one, it returns the existing one.

So a === b is true, meaning both are the same instance.


✅ Singleton Pattern – Recap with Interview-Ready Notes
🔧 Problem It Solves:
Ensures only one instance of a class exists throughout the application.
Useful when exactly one object is needed to coordinate actions across the system.

📌 Real-World Use Cases:
Database Connection Manager
Prevents multiple connections being created unnecessarily.

Logger
Centralizes all logging to a single place so logs are consistent and easy to trace.

Configuration Manager / Settings Loader
One place to load and manage app config (e.g., API URLs, secrets).

Cache Manager
Ensures a shared in-memory cache across components.

Authentication Manager
Only one object should handle and remember login tokens/session data.


🎯 Interview Tip:
If asked “Why not just use a normal class?”
You answer:
"Because with a normal class, every new call creates a new instance, which can cause data inconsistency or unnecessary resource usage. Singleton solves this by returning the same instance every time."
