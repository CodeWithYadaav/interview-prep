📍 Observer Pattern (In-Depth for Interviews)
🤔 What Is It?
The Observer Pattern is a behavioral design pattern where an object (called Subject) maintains a list of dependents (Observers) and notifies them automatically when its state changes.

🔧 Problem It Solves:
You want multiple parts of your system to react to changes in another part — without tightly coupling them.

📦 Real-World Use Cases:
Use Case	Why It's a Good Fit
UI frameworks (React, Vue)	Re-render when data changes
Notification systems	Notify all users when event occurs
Stock price ticker	Update multiple displays in real-time
Chat app	Everyone in a room gets new messages
Event Emitters (Node.js)	Observer pattern in core


// The Subject
class NewsAgency {
  constructor() {
    this.subscribers = [];
  }

  subscribe(subscriber) {
    this.subscribers.push(subscriber);
  }

  unsubscribe(subscriber) {
    this.subscribers = this.subscribers.filter(sub => sub !== subscriber);
  }

  notify(news) {
    this.subscribers.forEach(sub => sub.update(news));
  }
}

// Observer Interface
class Subscriber {
  constructor(name) {
    this.name = name;
  }

  update(news) {
    console.log(`${this.name} received news: ${news}`);
  }
}



const agency = new NewsAgency();

const user1 = new Subscriber("Alice");
const user2 = new Subscriber("Bob");

agency.subscribe(user1);
agency.subscribe(user2);

agency.notify("🚨 New article on design patterns!");

// Output:
// Alice received news: 🚨 New article on design patterns!
// Bob received news: 🚨 New article on design patterns!


✅ Interview Tip:
"Why would you use Observer over directly calling functions?"
You answer:
"It decouples the sender and receivers. The subject doesn’t need to know what the observers do, only that they implement an update method. This allows adding/removing subscribers at runtime."


🧠 Key Concepts Summary:
| Concept        | Explanation                                       |
| -------------- | ------------------------------------------------- |
| Subject        | Maintains list of observers                       |
| Observer       | Has an `update()` method to respond to changes    |
| Loose coupling | Subject doesn't need to know observers' internals |
| Dynamic update | Observers can be added/removed at runtime         |
