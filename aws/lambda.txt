✅ "Tell me about AWS Lambda" — Sample Interview Answer
AWS Lambda is a serverless compute service that lets you run code without provisioning or managing servers. You just upload your code, and Lambda runs it in response to events like HTTP requests (via API Gateway), S3 uploads, DynamoDB updates, or scheduled jobs.
I’ve used Lambda primarily for building microservices, data processing, and event-driven architecture, where code needs to run on-demand with auto-scaling, and billing is done only per execution time.



| Concept                   | Description                                                                        |
| ------------------------- | ---------------------------------------------------------------------------------- |
| **Trigger-based**         | Runs in response to events from S3, API Gateway, DynamoDB, etc.                    |
| **Stateless**             | Each invocation is isolated; no persistence unless stored externally (e.g. S3, DB) |
| **Cold Start**            | Delay during first invocation or after idle period                                 |
| **IAM Roles**             | Lambda uses execution roles to access AWS services                                 |
| **Timeout & Memory**      | Configurable (max 15 minutes, 10 GB memory)                                        |
| **Environment Variables** | For configuration management                                                       |
| **Layers**                | Share common dependencies across Lambdas                                           |
| **Concurrency**           | Supports provisioned and reserved concurrency for scaling control                  |



❓ 1. What are the main use cases of Lambda?

REST APIs via API Gateway
File processing when files are uploaded to S3
Cron jobs using EventBridge
Real-time data processing from DynamoDB or Kinesis streams
Backend logic for mobile/web apps (using Cognito + API Gateway + Lambda)



❓ 2. What is a cold start in Lambda and how do you handle it?
Answer:
A cold start happens when Lambda starts a new instance — it loads the runtime and code before executing, causing delay (100ms to seconds).
To reduce cold starts:
Use smaller packages and minimal initialization code
Use provisioned concurrency
Prefer lighter runtimes like Node.js or Go






❓ 3. How do you secure a Lambda function?

Use IAM roles to give least privilege access to AWS services.
For API Gateway-triggered Lambdas, use:
Cognito authorizers or
JWT validation in code.
Store secrets in AWS Secrets Manager or Parameter Store, not in environment variables directly.



❓ 4. How do you handle deployments and versioning?

I use CI/CD pipelines (e.g., GitHub Actions or CodePipeline) to deploy.
Lambda supports versions and aliases — making it easy to roll back or do canary deployments using aliases like dev, prod.





❓ 6. What’s the difference between Lambda and Fargate?
| Feature  | Lambda                    | Fargate                                 |
| -------- | ------------------------- | --------------------------------------- |
| Type     | Serverless Functions      | Serverless Containers                   |
| Duration | Max 15 min                | Long-running supported                  |
| Use Case | Event-driven, short tasks | Container-based apps, background jobs   |
| Control  | Fully managed             | More flexibility (e.g., Docker support) |




❓ 7. How do you handle errors and retries in Lambda?

For async invocations, Lambda retries twice by default.
You can use:
Dead Letter Queues (DLQ) with SNS or SQS
Lambda Destinations for success/failure
Structured logs in CloudWatch for debugging


❓ 8. What are Lambda Layers?
Lambda Layers let you package shared code or libraries (e.g., node_modules, Python packages) and reuse them across multiple functions — reducing duplication and deployment size.





❓ 9. How do you test Lambda functions locally?
I use AWS SAM CLI or Serverless Framework.
Also test using Postman or curl via deployed API Gateway routes.
