JavaScript Runtime Concepts

Understanding Call Stack, Heap, Event Loop, and More

📚 Call Stack

The call stack is a LIFO (Last In, First Out) data structure that tracks function calls.

function first() { console.log("First function"); second(); } function second() { console.log("Second function"); third(); } function third() { console.log("Third function"); } first(); // Start execution
Call Stack Execution Flow: Step 1: first() called ┌─────────────┐ │ first() │ ← Top of stack └─────────────┘ Step 2: second() called from first() ┌─────────────┐ │ second() │ ← Top of stack ├─────────────┤ │ first() │ └─────────────┘ Step 3: third() called from second() ┌─────────────┐ │ third() │ ← Top of stack ├─────────────┤ │ second() │ ├─────────────┤ │ first() │ └─────────────┘ Step 4: third() completes and is popped ┌─────────────┐ │ second() │ ← Top of stack ├─────────────┤ │ first() │ └─────────────┘ Step 5: second() completes and is popped ┌─────────────┐ │ first() │ ← Top of stack └─────────────┘ Step 6: first() completes - stack is empty (Stack is empty)

🏗️ Heap

The heap is where objects and dynamic data are stored. It's unstructured memory.

// Variables on call stack point to objects in heap let person = { // Object stored in heap name: "John", age: 30 }; let numbers = [1, 2, 3]; // Array stored in heap let greeting = "Hello"; // String stored in heap (in most cases) // Stack contains references to heap objects
Memory Layout: CALL STACK HEAP ┌─────────────┐ ┌─────────────────────┐ │ person │─────────────→│ { name: "John", │ │ (ref) │ │ age: 30 } │ ├─────────────┤ ├─────────────────────┤ │ numbers │─────────────→│ [1, 2, 3] │ │ (ref) │ ├─────────────────────┤ ├─────────────┤ │ "Hello" │ │ greeting │─────────────→│ │ │ (ref) │ └─────────────────────┘ └─────────────┘ Stack: Stores primitive values and references Heap: Stores objects, arrays, functions

🔄 Event Loop

The event loop manages asynchronous operations and coordinates between call stack and callback queues.

console.log("Start"); setTimeout(() => { console.log("Timeout callback"); }, 0); Promise.resolve().then(() => { console.log("Promise callback"); }); console.log("End"); // Output: // Start // End // Promise callback // Timeout callback

⚡ LibUV

LibUV is a C++ library that provides Node.js with async I/O capabilities and thread pool.

const fs = require('fs'); const crypto = require('crypto'); // File operations use libuv thread pool fs.readFile('large-file.txt', (err, data) => { console.log('File read complete'); }); // CPU-intensive operations use libuv thread pool crypto.pbkdf2('secret', 'salt', 100000, 64, 'sha512', (err, key) => { console.log('Crypto operation complete'); }); // Network operations use libuv event loop const http = require('http'); http.get('http://example.com', (res) => { console.log('HTTP request complete'); });

👷 V8 Worker Threads

Worker threads allow running JavaScript in parallel, each with its own V8 isolate.

// Main thread (main.js) const { Worker, isMainThread, parentPort } = require('worker_threads'); if (isMainThread) { // Main thread const worker = new Worker(__filename); worker.postMessage({ num: 1000000 }); worker.on('message', (result) => { console.log('Result from worker:', result); }); } else { // Worker thread parentPort.on('message', ({ num }) => { // CPU-intensive calculation let result = 0; for (let i = 0; i < num; i++) { result += i; } parentPort.postMessage(result); }); }
Worker Threads Architecture: Main Thread Worker Thread 1 Worker Thread 2 ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ │ V8 Engine │ │ V8 Engine │ │ V8 Engine │ │ Event Loop│ │ Event Loop│ │ Event Loop│ │ Heap │ │ Heap │ │ Heap │ │ Stack │ │ Stack │ │ Stack │ └─────────────┘ └─────────────┘ └─────────────┘ │ │ │ └─────────── MessageChannel ──────────────────────────┘ (SharedArrayBuffer for shared memory)

🔀 How Multithreading is Achieved

Node.js achieves multithreading through LibUV's thread pool and Worker Threads.

🔄 LibUV Thread Pool

  • Background I/O operations
  • File system operations
  • CPU-intensive crypto operations
  • Default 4 threads (UV_THREADPOOL_SIZE)

👷 Worker Threads

  • Parallel JavaScript execution
  • Own V8 isolate and event loop
  • CPU-intensive tasks
  • Message passing between threads

⚖️ Microtasks vs Macrotasks

Understanding the priority queue system in JavaScript's event loop.

🔬 Microtasks (Higher Priority)

  • Promise callbacks (.then, .catch, .finally)
  • process.nextTick() (Node.js)
  • queueMicrotask()
  • MutationObserver callbacks

📦 Macrotasks (Lower Priority)

  • setTimeout() / setInterval()
  • setImmediate() (Node.js)
  • I/O operations
  • UI rendering
console.log('1: Start'); // Macrotask setTimeout(() => console.log('2: setTimeout'), 0); // Microtask Promise.resolve().then(() => console.log('3: Promise')); // Microtask (Node.js) process.nextTick(() => console.log('4: nextTick')); console.log('5: End'); // Output: // 1: Start // 5: End // 4: nextTick (highest priority microtask) // 3: Promise (microtask) // 2: setTimeout (macrotask)
Event Loop Processing Order: 1. Execute all synchronous code 2. Process ALL microtasks (until queue is empty) 3. Process ONE macrotask 4. Process ALL microtasks again 5.
